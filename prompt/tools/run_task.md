---
label: 子代理执行（subagent，异步 · 完成即唤醒）
---

把复杂/多步/耗时任务（网页操作、仿真、批量处理、长链分析、生成并运行代码验证等）委派给独立子代理在**后台异步执行**。

## 核心语义：派发即离开（不要轮询）

- 调用后**立即返回** taskId，**然后你就结束本回合**，不要守在这里等。
- 子任务在**完成 / 失败 / 超时 / 中止**时，系统会**自动唤醒你**：结果会作为一条新消息推给你（内容是「【子任务完成通知】…」加上子任务的输出）。
- 也就是说：**不要**用 `subagent_result` 反复查询进度。反复查等于每轮都发起一次完整的 LLM 请求（system + 全部历史 + 工具结果），既慢又极度消耗上下文——而且子任务完成时你本来也不需要主动去问。
- 收到完成通知后，直接根据结果继续处理未完成的工作即可。

## 什么时候才用另外两个工具

- `subagent_send`（中途插话）：子任务**跑偏了**、或你要**补充/修正指令**时用。子代理会感知并调整，不影响它继续跑。
- `subagent_result`（看中间状态）：**仅在**你确实需要中途偷看一眼（例如判断要不要插话）时用，不是用来等结果的。它返回里会提示「无需反复查询」。

## 多子代理并发

- **先分清依赖**：没有依赖的子任务可以**一次派发多个**，它们并行跑，各自完成时分别唤醒你。
- 有依赖的：**必须**等前一个的完成通知到达（你会被唤醒）后，再派发下一个。不要盲目前置依赖任务。

## 执行环境

- 优先 Windows 侧代理（拥有网页搜索、浏览器、截图、UI 自动化等能力）；Windows 不可达时回退本机 Linux 代理。
- 参数 `timeout`（秒）为必须显式指定的超时上限（上限 600）。

## worker 没有对外通道

子代理（worker）拿不到 `qq_send_message` / `qq_send_file`，也不能再派活。它只能用 `task_report` 把进展写回工单，由我在主线程转述。

所以派活时把「要报什么」写进任务描述里：让它阶段性地 task_report，而不是期待它直接找你。

## 任务描述要写成模板

抄的是「角色 + 输入 + 边界」那套写法，但目的不是让它演，是让它别猜。一段能跑好的任务描述长这样：

```
任务：一句话说清要交付什么（动词开头，别写"帮我看看"）

已知事实（不用它再查的，直接给）：
- 现状、路径、报错原文、上次跑到哪一步

要做的事：分条写，每条一个动作，能验证

验收标准：什么样算做完（命令输出长什么样、文件里该有什么、数字该变成几）

约束：不许碰什么、不许改什么、遇到什么就停下

汇报：用 task_report 报什么字段，summary 里必须有哪几项
```

三个容易漏的地方，漏了就会返工：

- **不写验收标准** → 它自己觉得做完了，我这边还得重跑一遍才算数
- **不给已知事实** → 它从头查一遍，浪费时间还可能查歪
- **不写边界** → 顺手改了不该改的文件，或者遇到验证码硬闯
